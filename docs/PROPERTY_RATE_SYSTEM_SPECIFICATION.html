Two-Way Property Rate Digital Administration Platform

Technical Architecture & Operational Specification Document
System Scope & Implementation Directives:
  1. Two-Way Interaction Model: The platform establishes a synchronized digital bridge between Municipal Revenue Administration (Client/Assembly) and Property Rate Payers (Citizens).
  2. Consolidated In-App Settlement: Replaces disconnected SMS hyperlinks with a unified, in-app digital demand notice and integrated payment gateway engine.
  3. Automated Assessment Rollout: Standardizes annual batch billing, carried-forward arrears consolidation, and automated notification dispatch.
SECTION 1 — BASELINE DATA STRUCTURE & FIELD SPECIFICATION
Core Data Schema, Field Definitions, and Architectural Purpose
Category Field Identifier Data Type & Format Functional Definition & System Purpose

Owner / Digital Address Alphanumeric (GPS Format) GhanaPost GPS digital address / Taxpayer ID; ties the property account to its physical location coordinates.

Total Amount Due Decimal / Currency Consolidated balance payable by the taxpayer (Arrears + Current Fee).
SECTION 2 — TWO-WAY SYSTEM ARCHITECTURE
Functional Modules, Integration Layers, and Bidirectional Workflows
Module A: Taxpayer Mobile Interface (Citizen Application)
  1. Telephone Authentication & Account Number Resolution: Taxpayers authenticate using their mobile telephone number via SMS OTP. The telephone number serves strictly as an authentication and verification mechanism. Once verified against records present in the database, the system resolves and displays all property Account Numbers (Account Heads) registered under that contact number.
  2. Native Digital Demand Notice Display: Provides an authenticated, mathematically transparent demand notice interface displaying Account No., Owner/Digital Address, Classification, Rate Calculation Formula, and Itemized Ledger in real time.
  3. Integrated In-App Settlement Engine: A native payment engine embedded directly on the bill supporting modular settlement options:
    • Full Balance Settlement: Settle total consolidated outstanding liability.
    • Arrears Settlement Only: Settle carried-forward prior debt independently.
    • Active Year Assessment Only: Settle current period fee independently.
  4. Multi-Channel Payment Gateway: Direct integration with Mobile Money payment rails (MTN Mobile Money, Telecel Cash, AT Money) and Bank Debit/Credit cards.
  5. Automated Proof of Payment Issuance: Upon instant payment gateway confirmation, the system generates an official authenticated digital receipt stored permanently within the taxpayer's account ledger.
Module B: Municipal Administration & Revenue Automation Portal
  1. Automated Annual Batch Billing Engine: Scheduled annual computation engine triggered during the opening fiscal window to compute assessments across all registered properties:
    Current Fee = Rateable Value × Rate Imposed
    Total Amount Due = Arrears + Current Fee
  2. Automated SMS Broadcast & Secure Token Dispatch: Mass messaging pipeline that delivers concise statutory billing alerts to telephone numbers registered on each property Account Number, containing secure single-session token links that open the specific bill directly within the mobile application.
  3. Revenue Analytics & Defaulter Tracking: Administrative dashboard providing real-time collection metrics filtered by Property Classification and Billing Status. Accounts with unpaid balances past the statutory settlement deadline (June 30) are automatically flagged for administrative follow-up.
SECTION 3 — END-TO-END OPERATIONAL WORKFLOW
Lifecycle Stages, Execution Hierarchy, and Financial Ledger Principles
Operational Phase System Action & Execution Logic Responsible Party Output / Deliverable
1. Annual Rollout System executes batch computation; assesses current year fees and rolls uncollected previous balances into arrears. Municipal Revenue Unit Annual Assessment Roll
2. Notification Dispatch Automated SMS engine broadcasts demand notices with encrypted deep-links to registered mobile telephone numbers tied to each property Account Number. Automated Messaging Service Direct Taxpayer Notification
3. Demand Notice Ingestion Taxpayer opens secure link; reviews itemized assessment, valuation factor, and arrears balance. Property Rate Payer Authenticated Bill View
4. In-App Settlement Taxpayer selects settlement amount (total amount due, arrears, or current fee) and authorizes transaction via payment gateway. Payment Gateway / Payer Real-Time Settlement Webhook
5. Ledger Reconciliation System database updates property ledger, reduces balance, and issues official digital receipt. Core Database Engine Official Digital Receipt
6. Statutory Enforcement Accounts with outstanding balances past statutory deadline (June 30) are flagged for administrative follow-up. Revenue Enforcement Unit Compliance & Follow-up List
Financial Ledger & Accounting Principles
  1. Priority Debt Allocation: All incoming payments are applied strictly against the oldest debt first. Settlements reduce carried-forward Arrears before liquidating the Current Fee.
  2. Partial Settlement Accounting: When partial payments are received, the system adjusts the arrears balance in real time while maintaining the active year fee structure until fully settled.
  3. Immutable Audit Logging: Every billing transaction, SMS dispatch event, bill view, and payment attempt is logged with an immutable timestamp, operator ID, and network reference for municipal audit compliance.
